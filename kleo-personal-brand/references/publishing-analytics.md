# Assets, publishing, distribution and measured learning

## Capability check

Resolve the actual tools available in the current host. Do not invent a LinkedIn API endpoint, OAuth scope, analytics permission, scheduled task, image renderer or browser session. For a new API integration, consult current official documentation; this skill itself does not provision one.

Writing and research can run from source material without access to the live account. Publishing requires the correct authorized account and supported tool path. A user asking for content does not automatically authorize comments, messages, profile changes or posts.

## Graphics and carousels

When requested or useful within the user's deliverable, choose a format that clarifies the idea: a simple comparison, process, annotated example, diagram or branded image. Use the client's actual palette, typography and asset restrictions if known. Do not invent a testimonial, screenshot or logo endorsement.

For an image-generation/design task, read the relevant available skill. Give it the approved message, audience, brand traits, layout, exact on-image text if needed and accessibility needs. Inspect the returned artifact for legibility, spelling, unsupported claims and alignment with the post. Provide alt text.

For a requested carousel, prepare one coherent argument across slides with a clear cover promise, useful progression and fitting ending. Use an available slide/design/document tool for actual output. If rendering/export is unavailable, deliver slide copy and a design brief with that limitation. Carousel production is an optional extension of this skill, not a verified native Kleo feature.

For lead magnets, match the resource to a single useful reader task and a relevant offer. Draft a delivery page/email only if requested. Hosting, forms, email delivery, follow-up and external publishing require actual tools and scope; do not pretend a designed funnel is already operational.

## Publishing state machine

Prepare → quality check → resolve authorization → execute → verify → record.

Before external execution, resolve:

| Item | Required match |
|---|---|
| Client/account | Profile URL or connected account identity belongs to the requested author |
| Content | Exact final version and attachments; no unresolved factual placeholders |
| Action | Publish now, schedule, edit profile, comment or message as actually requested |
| Timing | Date, time and timezone for scheduling; resolve ambiguity before execution |
| Authorization | Human instruction covers this action/content/account, including any standing scope |
| Tools | Supported write path and current tool permissions are available |

Do not ask again when these are already covered. If authorization is missing, complete the draft/package first and ask for the specific remaining action. A broad “manage my brand” request permits planning/drafting; it is not enough to send DMs. If the user asks for a publishable draft, deliver it rather than turning the response into an approval request.

Use a connected publishing tool when supported, otherwise a permitted browser workflow. Inspect the UI for the selected account and composed content. When scheduling, verify the timezone displayed by the destination. On success, save the post URL or scheduled entry, exact version and timestamp. Do not claim automatic posting merely because a date appears in a calendar file.

If a write result is ambiguous or a timeout occurs, read the destination first. Search the account's visible posts/queue for the exact draft before retrying. Duplicate publication is worse than an honestly unverified status. If read-back is unavailable, mark `unverified` and ask for the smallest necessary check. Do not issue another write blindly.

Profile updates follow the same account/scope/verification pattern. Preserve unrelated profile fields. Comment/DM drafts must relate to a real source and must not invent a personal relationship. Explicit authorization is required to send them. No bulk outreach, account-control bypass or automated engagement campaign is included by default.

## Recurrence

When the user explicitly asks for recurring work, use the host's automation tool if available. Save the active client workspace, schedule/timezone, permitted work, input refresh method and expected output. Preserve notification intent; keep unchanged runs quiet unless the user asked for routine reports. A content calendar or a memory entry is not a running automation. Say so if the tool is unavailable.

## Collect analytics honestly

Use authorized analytics tools, user-selected dashboard, export or supplied data. Capture source, observation time, reporting window, post date, elapsed time since publication and metric definitions. The author's private metrics are not available merely because their public profile is accessible.

Available data may include impressions, reach, reactions, comments, reposts, profile views, follower changes, saves, clicks, inquiries and conversions. Record only fields the source provides. Missing means unknown, not zero. Do not call publicly visible engagement “full analytics.”

Define metrics before comparison:

- Engagement rate by impressions = `(reactions + comments + reposts) / impressions * 100`, when those fields are available and defined consistently. If the source includes clicks/saves, name that alternate formula explicitly.
- Click rate = `link clicks / impressions * 100` when both exist and refer to the same post/window.
- Inquiry/conversion counts require actual tracked events or client-reported evidence; label attribution accordingly.
- A zero or missing denominator yields undefined, not 0%. Do not average missing data into a result.

Compare like with like: same elapsed observation window where possible, comparable formats and similar audience conditions. Use a median across a relevant set to avoid letting one outlier dominate. Separate a per-post mean from a pooled rate; they answer different questions.

## Turn data into editorial decisions

1. Summarize the goal and what data is actually available.
2. Identify observations: topic, format, hook type, specificity, CTA, audience responses and outcomes.
3. Explain limitations: small sample, unequal age, paid distribution, external events, missing attribution or a changed audience.
4. Propose plausible explanations as hypotheses; do not state causality from a few posts.
5. Select 1–2 experiments that change one meaningful variable, name the success signal and observation period.
6. Record continue/change/stop decisions with evidence and update the strategy, not the author's permanent voice, unless preference feedback supports that change.

For a sales goal, a high-impression general post may be less valuable than a lower-reach specialist post producing relevant conversations. Do not optimize away the author's positioning or truthfulness to chase engagement.

If no analytics exist, establish a baseline collection plan and make a hypothesis-based content plan. Do not announce “best-performing pillars” from unavailable data. Ordinary editing feedback can improve voice immediately; performance learning requires measured evidence.

## Review output

Deliver a compact review: what happened, what can be concluded, what remains uncertain, and the next tests. Include links or source rows supporting the findings. Save original data separately from computed results, and preserve formulas/definitions for the next review.
